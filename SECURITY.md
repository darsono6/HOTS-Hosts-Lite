# Security Policy

[← Back to README](README.md)

## Overview

HOTS Hosts Lite is an open-source Windows utility for managing the system `hosts` file, custom domain blocking, application (firewall) blocking, and a hosts-file lock.

Because some features make system-level changes and require Administrator privileges, security issues are taken seriously.

The source code is publicly available in this repository.

## Reporting a vulnerability

If you believe you have found a security vulnerability in HOTS Hosts Lite, please **do not disclose sensitive details publicly before contacting the maintainer**.

Please report security issues privately by email:

**hots.support@gmail.com**

Where possible, include:

- HOTS Hosts Lite version
- Windows version
- affected feature or component
- clear description of the issue
- steps to reproduce
- expected and actual behavior
- screenshots, logs, or proof-of-concept information if relevant

Please do not include passwords, personal data, or other sensitive information that is not necessary to reproduce the issue.

## What should be reported

Examples of security issues include:

- unintended privilege escalation
- arbitrary code execution
- bypasses of domain-blocking or application-blocking restrictions
- unauthorized modification of protected files or the stored password hash
- unsafe handling of Administrator privileges
- insecure file or configuration handling
- vulnerabilities that could allow another local application or user to abuse HOTS Hosts Lite

General bugs, usability problems, false positives from diagnostic heuristics, and feature requests can be reported through GitHub Issues instead.

## Threat model

HOTS Hosts Lite performs legitimate system-level operations because that is required for several of its features.

The application is **not** designed to defend a system against a user or attacker who already has unrestricted Administrator privileges.

In particular, the domain- and application-blocking features are intended primarily to reduce casual or inexperienced bypass attempts. They should not be considered an enterprise-grade security boundary.

Application blocking is path-based: a firewall rule applies to one exact executable file. For programs installed in version-numbered folders, HOTS Hosts Lite moves the rule to the current version when it starts and when the Features page is opened, so a program updated while HOTS Hosts Lite is closed is not blocked until then. Copies of a program in other locations are not covered.

## Supported versions

Security fixes are primarily intended for the latest released version.

| Version | Security support |
|---|---|
| Latest release | Supported |
| Older releases | Best effort |
| Development versions | Not guaranteed |

Users are encouraged to update to the latest release.

## Administrator privileges

Depending on which features are enabled, HOTS Hosts Lite may modify:

- the Windows `hosts` file
- backup copies, profile snapshots and the custom-domain list, stored next to the `hosts` file in the `drivers\etc` folder
- Windows Firewall rules (created and removed by the application, named `HOTS_FW_*`; when a blocked program is updated into a new version folder, its rule is recreated for the new path and the old one removed)
- file-system ACLs
- the Windows Registry (startup password protection)
- the DNS resolver cache (flushed after saving the `hosts` file)

To do this, the application calls built-in Windows tools: `powershell.exe` (file ACLs), `netsh.exe` (firewall rules) and `ipconfig.exe` (DNS cache). Program settings are stored per user in `%APPDATA%\HOTS Hosts Lite`; the state of the hosts file lock and of the firewall blocks is kept in `%ProgramData%\HOTS Hosts Lite`.

These operations are intentional parts of the application.

Users should review the documentation and source code before enabling system-level features they do not need.

## Privacy and network communication

HOTS Hosts Lite does not require an online account for normal operation.

The application is designed primarily to operate locally.

Features that can involve network communication include, depending on the action performed:

- the built-in update checker, which contacts GitHub Releases to look for newer versions — by default it runs automatically at startup and can be switched off on the About page
- the domain-existence diagnostic, which sends the host names from your `hosts` file as DNS queries to a public resolver (Google Public DNS, `8.8.8.8`); before the scan it also tests connectivity with short TCP connections to public DNS servers (`1.1.1.1`, `8.8.8.8`, `1.0.0.1`, port 53)
- any network activity initiated by Windows or third-party components affected by the user's configuration

This project does not claim that every network request generated by Windows itself can be attributed to HOTS Hosts Lite.

The application writes a local diagnostic log (`error.log`) to `%APPDATA%\HOTS Hosts Lite`. It stays on your computer and is not sent anywhere. Please review it before attaching it to a public issue.

## Backups and system changes

Where a feature supports rollback, HOTS Hosts Lite may save the previous state before applying a change.

Users should still maintain independent system backups and should consider creating a Windows System Restore point before making substantial configuration changes.

## Uninstallation

Since this update, uninstalling HOTS Hosts Lite first shows an "Are you sure?" prompt reminding you that installing a newer version does not require uninstalling first (just run the new installer directly — it updates the program in place without touching your settings or domain list). This prompt is shown in whichever language the application is currently set to.

Unlike the full HOTS Hosts, this edition has no parental-control feature, so there is no "prevent a child from bypassing the blocks by uninstalling" scenario to protect against — **uninstalling no longer requires the startup password**, even if one is set. The password still protects opening the app itself.

After that, a small wizard lets you choose what to do with the changes HOTS Hosts Lite made to your system. Some cleanup always happens regardless of your choices, because leaving it undone would break the system rather than just leave a preference in place; everything else is optional and off unless the wizard says otherwise.

**Always removed, regardless of your choices in the wizard:**

- the hosts file lock (the deny-write ACL entry for the Users group on the `hosts` file)
- the application's registry keys, including the stored password hash

This runs unconditionally because an orphaned ACL lock would leave the `hosts` file permanently non-editable, with no app left to unlock it.

**Optional, selected individually in the uninstall wizard (unchecked options are left as they are):**

- **Domain and app blocks** — removes only the hosts entries HOTS Hosts Lite itself added (matched by internal markers; entries you or another program added manually are never touched), and removes every currently-active Windows Firewall rule the application created (`HOTS_FW_*`). Checked by default.
- **Saved configuration** — deletes the application's data folders (`%ProgramData%\HOTS Hosts Lite` and `%APPDATA%\HOTS Hosts Lite`) and the saved profile slots (`HOTS_profiles`) that live next to the `hosts` file in `drivers\etc`. Checked by default.
- **Custom domain list** — deletes `custom_domains.txt` (the list typed in under "Block your own domains"), which also lives next to the `hosts` file. **Unchecked by default**: the application promises that this list survives uninstalling, so you can reuse it after reinstalling. Removing the blocks from the `hosts` file does not delete this list.
- **Hosts file backups** — deletes the automatic backups HOTS Hosts Lite created, across all three profiles: alongside the `hosts` file itself (profile 1) and in the two dedicated folders `HOTS_backups\profile_2` and `HOTS_backups\profile_3` (profiles 2 and 3). Checked by default when any exist.

Anything left unchecked stays on the computer after HOTS Hosts Lite is removed — for example, if you leave "Domain and app blocks" unchecked, the blocked domains and the firewall-blocked apps stay blocked even with the app gone, until you remove them yourself.

## Installing over an existing version

Running the installer over an existing installation (whether to update or repair) first asks Windows to close any running instance of HOTS Hosts Lite, then deletes the entire installation folder before copying the new files. This is intentional: the installation folder never contains user data (settings, password, domain list, profile slots and backups all live outside it, in `%ProgramData%`, `%APPDATA%` and `drivers\etc`, and are never touched by this), and it avoids leaving orphaned files behind from older versions.

## Responsible disclosure

Please allow reasonable time for investigation and remediation before publicly disclosing a confirmed vulnerability.

Security reports help improve HOTS Hosts Lite and are appreciated.
